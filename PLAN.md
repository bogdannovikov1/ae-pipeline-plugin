# План плагина для видео в After Effects

Плагин для Claude Code, который превращает написанный текст и запись голоса в готовое видео с анимацией в After Effects. Голос и финальное решение остаются за автором, рутину берут на себя агенты.

## Главные принципы

1. **Этапы общаются файлами, а не чатом.** Каждый этап получает готовый файл, отдаёт новый и может идти в отдельной сессии. Так дешевле по токенам и можно перезапустить любой этап.
2. **Каждый этап заканчивается ревью автора.** Следующий этап не стартует без подтверждённого результата предыдущего.
3. **Анимация собирается из проверенных блоков, а выбор делает автор.** Агент предлагает: взять готовый блок из базы или сделать новый на основе принципов. Сам он этого не решает. Одобренный новый блок попадает в базу, так она и пополняется.
4. **Правки автора никогда не затираются.** Это касается и транскрипта, и анимации в AE.
5. **Всё работает на одном фрагменте, прежде чем становится плагином.** Сначала полный проход по одному короткому фрагменту, потом обобщение.

## Конвейер

| № | Этап | Кто делает | Вход | Результат | Ревью |
|---|---|---|---|---|---|
| 0 | Подготовка | Автор | Идея | Запись голоса | — |
| 1 | Транскрипт | Агент `transcriber` | Аудио 30 с – 3 мин | `<фрагмент>.timeline.json`, `<фрагмент>.notes.md` | В AE маркерами |
| 2 | Финальный транскрипт | Скрипт | Маркеры в AE | Обновлённый `timeline.json`, статус `approved` | Краткий отчёт |
| 3 | План анимации | Агент `director` | Транскрипт, база, стиль | `<фрагмент>.animation.json` с описанием словами | В чате |
| 4 | Сборка анимации | Агент `animator` | План, база, ассеты | `<фрагмент>.scene.json`, композиция в AE | Рендер кадров, затем AE |
| 5 | Доводка | Автор и `animator` | Композиция | Сохранённый фрагмент | Автор |
| 6 | Склейка | Агент `editor` | Все фрагменты | Финальное видео | Автор |

### 1–2. Транскрипт

Работает модель `whisper-large-v3-turbo` через `mlx-whisper` локально на Mac, затем подрезка границ по громкости. Агент записывает предупреждения в `notes.md` и предлагает ревью.

После ревью транскрипт замораживается: дальше на него ссылаются номера слов.

### 3. План анимации

Автор и агент обсуждают, что показать. Агент опирается на базу и описание стиля, а при сомнениях уточняет. Вопросы задаёт пачкой, а не по одному, чтобы диалог был коротким.

Копию транскрипта делать не нужно: файл анимации ссылается на номера слов. Так таймкоды не разойдутся в двух файлах. Для чтения агент показывает объединённый вид: текст и анимации рядом.

```json
{
  "transcript_hash": "...",
  "beats": [
    {
      "at_word": 3,
      "until_word": 4,
      "intent": "Появляется массив из пяти клеток",
      "block": "array_cells_in",
      "params": { "count": 5 },
      "status": "approved"
    }
  ]
}
```

Для каждого бита агент спрашивает автора, брать готовый блок или делать новый. Если выбран новый, `block` остаётся пустым, а `intent` становится заданием для следующего агента. Хэш защищает от работы по устаревшему транскрипту.

### 4–5. Сборка и доводка

Агент превращает план в сцену, а постоянный отлаженный JSX строит по ней слои, анимацию и звуки. Перед показом автору агент рендерит ключевые кадры через `aerender`, смотрит на них и исправляет явные проблемы.

Новый блок агент пишет отдельным JSX-файлом только по решению автора. В базу блок попадает, когда автор его одобрил.

Слои, созданные скриптом, помечаются. Ручные правки защищаются так:

- до начала ручной доводки сцену можно пересобирать полностью;
- после неё агент меняет только указанные биты, а блокированные слои не трогает;
- перед пересборкой сохраняется версия проекта.

### 6. Склейка

Каждый фрагмент рендерится в файл, агент собирает их по порядку с короткими незаметными переходами и проверяет стыки звука. Сборка через `ffmpeg` проще и надёжнее общего проекта AE, но подходит только для простых переходов. Сложные переходы потребуют сборки в AE.

## База

Базы лежат в `~/Documents/Projects/Videos/bases/`, первая — `base_algoritms`. Позже такие папки подключаются в настройках плагина.

С базой работаем только через агента `librarian`: он подтверждает с автором, что добавить или удалить, и держит файлы и `assets.json` согласованными. Вручную файлы в базе не меняем.

```text
base_algoritms/
  base.json            паспорт базы для подключения
  style.md             почерк: темп, принципы, что нельзя делать
  tokens.json          цвета, шрифты, размеры, кривые, длительности
  blocks/              проверенные анимации: код, описание, параметры, превью
  assets/              общие картинки, видео, звуки
  assets/assets.json   описания ассетов
  references/          кадры и видео, на которые равняемся
```

Папка видео:

```text
<видео>/
  fragments/<фрагмент>/
    <фрагмент>.wav
    <фрагмент>.timeline.json
    <фрагмент>.notes.md
    <фрагмент>.animation.json
    <фрагмент>.scene.json
    assets/
  output/
```

## Узкие места

| Риск | Уровень | Почему это проблема | Что делаем |
|---|---|---|---|
| Генерация красивой анимации | Критический | Код с нуля часто падает, а «красиво» трудно описать словами | Блоки, токены, референсы и рендер кадров для самопроверки |
| Описание стиля | Критический | Текстом почерк не передать | Числа в `tokens.json`, разбор ваших лучших работ, база из 5–10 реальных блоков |
| Ручные правки против пересборки | Высокий | Повторный запуск может стереть доводку | Метки слоёв, частичная пересборка, версии |
| Обратная связь из AE | Высокий | Агент не видит результат, а настройка записи в AE блокирует часть обмена | Рендер кадров через `aerender`, проверка настройки перед работой |
| Склейка | Средний | Стыки звука и стиль переходов легко заметны | Проверить на двух фрагментах заранее |
| Расхождение файлов | Средний | Правка транскрипта ломает план | Заморозка и `transcript_hash` |
| Наполнение базы | Средний | Без описаний ассеты бесполезны, а поддержка требует времени | Единый файл описаний, блоки добавляются только после одобрения |
| Токены | Средний | Длинный диалог и большие JSX дорого обходятся | Отдельные сессии, JSON вместо готового кода |
| ExtendScript | Низкий сейчас | Старая технология, зависит от Mac и версии AE | Код блоков отделён от описаний и данных |

## Порядок разработки

1. **Закрыть этап транскрипта.** Готово: `notes.md`, заморозка и статус `approved`.
2. **Собрать первую базу.** 5–10 блоков из ваших реальных анимаций и первая версия `tokens.json`.
3. **Сделать движок сцен.** Постоянный JSX строит композицию из `scene.json`.
4. **Пройти один короткий фрагмент руками.** Весь путь от транскрипта до готового фрагмента, без агента-режиссёра. Это главная проверка плана.
5. **Добавить агента `director`.**
6. **Добавить агента `animator`,** рендер кадров и создание новых блоков.
7. **Прогнать целый ролик** и добавить защиту ручных правок.
8. **Добавить агента `editor`** и склейку.
9. **Упаковать в плагин.** Агенты, навыки, скрипты и установка.
